# PhotographerEye

Portable JPG/JPEG/PNG, HEIC/HEIF/AVIF and RAW photo viewer for Windows (WPF, .NET 8, single `.exe`), with tone correction (shadows, gamma, histogram stretch) and saving of edited photos.

## Features

- Folder image browsing, navigation (arrows, Home/End); the ←/→ arrows switch photos always — even when a slider has focus (text editing takes priority)
- Fast RAW preview: the built-in camera thumbnail (LibRaw, largest of the thumbnail list) appears in ~0.3 s on open and arrow-key switching, before the full 16-bit decode lands; the thumbnail is rotated immediately per EXIF orientation (tag 274 — from the JPEG thumbnail or the file), and dimensions read from the RAW header (no decompression) swap axes for portrait orientation — aspect ratio and fit-to-window are correct from the first frame; neighbor thumbnails (±1) are pre-decoded in the background (preview cache active)
- Bottom bar, right side: file metadata when known — camera model, date, focal length, aperture, ISO, shutter speed (LibRaw for RAW, own TIFF parser for HEIC/HEIF/AVIF, `BitmapDecoder` EXIF for JPG/PNG/TIFF); loaded in the background after the image arrives, stays empty when the file has no data
- HEIF photos — HEIC/HEIF/HIF (iPhone and others) and AVIF — decoded straight from the file by the bundled LibHeif (LibHeifSharp + libheif with libde265/libx265/aom, no WIC/Store dependency), full input resolution into all corrections; container-transform orientation (`irot`/`imir`/`clap`, applied by the decoder) takes precedence, EXIF orientation applied only when absent; no support for encrypted files (Apple `.HEIC` with encrypted photos needs prior decryption), 10-bit HDR (HDR/SDR render with 8-bit conversion)
- Zoom 10–400%: mouse wheel, `+`/`-`, `1` — 100%, `0`/"Fit" button — fit to window, double-click — fit/100% toggle
- Pan: mouse drag (when the image is larger than the window); the image is always centered and never cropped
- Shadow correction −100…+100 (tonal mask above black, lifts deep shadows and spares halftones; linear sRGB pipeline) and gamma 0.50–2.00 (mid-tone LUT)
- Photoshop-style sliders: clicking the track sets the value at the clicked spot; dragging the **label or number** next to a slider adjusts precisely (Shift ×10 faster, Ctrl/Alt ×0.1 finer); **double-clicking the number** lets you type an exact value; Shift+arrows — big step, Ctrl+arrows — smallest step (0.01 EV); double-click the track or the ♻ button resets the correction
- Compare with the original: hold the "Compare" button or space (preview without corrections; releasing returns)
- Crop & rotate (toolbar "Crop" button or the `C` key): non-destructive, full-resolution crop with a live overlay — drag inside the frame to move it, drag the 8 handles (corners/edges) to resize (crop scaling), drag outside the frame or `Ctrl`+drag anywhere (also inside the frame) to straighten (free rotation ±45°, auto-inset so no empty corners ever appear; rule-of-thirds grid plus a finer 8×8 grid shown during straightening and handles); mouse wheel zooms the image also while cropping (anchored under the cursor, `Shift`+wheel pans); while dragging, the change renders instantly on a downscaled preview (rotation and cropping stay fluid even on full 24 Mpx 16-bit RAWs — the full-resolution render runs once, in the background, when the drag ends or a geo button is clicked); adjustments (toolbar sliders, panel, histogram stretch) are disabled while crop mode is open so slider changes can't fight the crop; aspect presets in the crop bar: Original (the image's own ratio, follows the rotated orientation), 3:2, 4:3, 16:9, 16:10; "Original frame" restores the original aspect ratio and full size; toolbar ⟲/⟳ rotate the image in 90° steps (orientation swap landscape ↔ portrait, the crop follows the content); `R`/Reset also removes crop and rotation; applied in the save path for both JPG (8-bit) and RAW (exact 16-bit planar: 90° rotations and crop re-arrange samples losslessly, free-angle uses bilinear resampling), stored in the `.eye` fingerprint (fields `Rot90`, `Angle`, `CropX/Y/W/H`, `CropAspect`) so it returns on reopen
- RAW file preview: RW2 (Panasonic), NEF/NRW (Nikon), ARW/SRF/SR2 (Sony), CR2/CR3/CRW (Canon), ORF (Olympus), RAF (Fuji), PEF (Pentax), DNG and others — bundled LibRaw: demosaicing, camera white balance, orientation auto-flip; **highlight reconstruction** (mixed LibRaw mode + clipping neutralization: burnt channels are rebuilt and clipped pixels desaturated to white — overexposed backgrounds don't shift magenta/violet), **16-bit-per-channel** decoding (48 bpp — native 12/14-bit sensor depth scaled to the full 0–65535 range, no step loss), on-screen preview with 4×4 Bayer dithering; **preview and all corrections always run at full resolution** (display scaled in the window); edit saving via dialog (JPG 90% / 16-bit TIFF) at full RAW resolution. **Camera tone curve for Sony**: for ARW/SRF/SR2 files the app derives the starting point from the JPEG preview embedded in the file — quantile matching of the scene luminance distribution (raw, after white balance) to the camera preview's displayed luminance distribution yields a monotonic scene curve in EV (32 knots, blacks preserved, highlight shoulder continued from the final segment), replacing the default tonal map in the base process (CPU and GPU); exposure/white balance work under the curve as in-camera; the fit is verified by gates (aspect match, pair count, spread, rank correlation, holdout-sample error better than the default map and within RMS) — failed gates (e.g. preview in another form, missing preview, unusual files) fall back to percentile auto-exposure; the curve is stored in the `.eye` fingerprint (the `ToneCurve` field) and session like `BaseEv`, and the Reset button adopts the new starting point. **Starting auto-exposure (other RAWs)**: exposure normalization is computed from the linear scene (dcraw-like 99.5th luminance percentile → ~0.93 of range, in EV), so RAW opens correctly exposed with no washed-out/darkened sliders; the value is stored in the `.eye` fingerprint (the `BaseEv` field) and session, and old saves (without the field) render as before — the Reset button adopts the new starting point
- Corrections panel (vertical bar on the right, slider button or the `E` key) — tonal model in the **linear scene**: RAW images work in the **linear scene** (LibRaw with gamma off), the base process is an **extended Reinhard** tonemap on luminance (EV LUT −14…+10 around 0.18 gray; whites shift the white point, blacks = soft knee/black lift, contrast = slope in EV) with sRGB encoding at the end; for JPG/PNG an S-curve in the gamma 2.2 domain (identity at neutral); **exposure** (±5 EV) as `2^EV` gain before the regions, **highlights/shadows** as local delta gains on log-luminance (smoothstep masks in EV around gray: shadows below +0.3 EV, highlights above −1 EV, factors 1.7) evaluated on an edge-aware base layer (fast guided filter on log-luminance, ~480 px grid, region radius 3% of the short side) so texture inside bright/dark regions keeps its local contrast and no halos form at edges; brightening rolls off toward white instead of clipping; highlights are desaturated to luminance at tonemap time (no magenta); **white balance** (temperature ±100, symmetric R/B in linear) with a **white-point eyedropper**, **clarity** (±100: large-radius local contrast with halftone weighting), **saturation** (±100: 0 neutral, −100 B&W, after tonemap), **sharpening** (0–150), **dehaze** (±100 haze subtraction on linear values — for RAWs with a camera curve applied after the tonemap in the display domain, so the slider responds just like for JPG/PNG), **noise reduction** (0–200, luminance grain) and **color noise reduction** (0–200, colored speckles and blotches) as two independent sliders: YCoCg planes in a noise-stabilized domain (sqrt of linear for RAW, encoded values for JPG/PNG) are decomposed with an undecimated B3-spline wavelet (4 luma / 5 chroma scales) and detail coefficients are shrunk with a Wiener-like gain whose threshold follows the noise measured on the photo itself, separately for every wavelet scale and 16 brightness bands (robust quantile and block-RMS estimates on a sparse grid, bumps caused by texture-only bands removed), so the stronger and coarser noise of dark areas — read noise, demosaicing blotches — is removed as well as midtone grain; edges and texture above the noise floor stay sharp while flat-area grain and color blotches disappear, and a clean photo is left almost untouched; a little fine luma grain is kept at strong settings; past 100 (very noisy photos: high ISO, pushed shadows) the luma threshold keeps growing at half the rate (1.5x the 100 value at 200; edges soften somewhat at the top of the range), the chroma one keeps its curve, the kept grain fades out to none at 200 and one coarser wavelet scale (5 luma / 6 chroma) ramps in from zero, so coarse blotches go too — 0–100 behaves exactly as before; color noise reduction additionally runs a 3×3 median on the two chroma planes (one pass at 1 px spacing for single-pixel dots, one dilated pass at 2 px spacing for the 3–5 px blobs typical of X-Trans/Bayer demosaicing) before a stronger chroma wavelet shrink — brightness detail is never touched by it (both values stored in the `.eye` file as `Denoise` / `ColorNoise`); `.eye` files from version 0.93 (old 0–200% saturation scale) convert automatically
- GPU-accelerated corrections: RAW edit operations (noise reduction, clarity, sharpening, highlights, shadows, white balance/contrast/saturation, curves) computed on the graphics card via DirectCompute (ComputeSharp) — result nearly identical to CPU (mean difference ~0.03 out of 65535), several times faster on a heavy correction set. Hardware GPU detected at startup (largest-memory discrete card preferred); with no GPU — or with `PHOTOGRAPHEREYE_GPU=0` — processing runs on CPU only (automatic fallback). Acceleration status shown in "About…"
- Histogram overlay (luminance + R/G/B overlays) computed from the final preview; shown only with the Adjustments panel open (opening triggers a fresh compute), hidden on image change; scale normalized to the 99th percentile of bin counts (clipping peaks trimmed at the top, the rest stays readable), channel fills closed along the baseline
- Manual histogram stretch: drag a point on the histogram — the part on one side of the point compresses, on the other stretches; points are **anchored in scene EV** (log-luminance relative to 0.18 gray) and enter the tonemap LUT **before sRGB encoding**; piecewise-linear maps in EV with pinned range ends, points keep monotonicity; more points added with further grabs; points removed by: double-clicking the histogram, the reset (♻) button at the overlay's ×, `R`/Reset. The toggle (⤮) at the × selects the mode: **bake into sliders** (default — end of drag converts the knot into Exposure/Highlights/Shadows/Whites/Blacks values per the knot's EV and clears the points, further drags accumulate into the sliders) or an **independent curve** (knots stay as an EV curve entering the tonemap LUT before sRGB encoding, so sliders work consistently under it — +1 EV exposure shifts the scene by exactly 1 EV under the unchanged curve)
- Adjustment Undo/Redo (Ctrl+Z / Ctrl+Y or the ⟲/⟳ buttons): history of the last **50** states per image; commit after 600 ms of slider silence and immediately on histogram-grab end, B&W toggle and other edit-changing actions; undoing past a point truncates possible redo. A plugin command or a tool press (e.g. a click with the heal tool) is a step of its own; when it changes nothing it does not split the edits around it, so moves of one slider before and after such a click stay one step (`BeginHistOp`/`EndHistOp`). The **History** plugin (`eyePlugins/history`, bundled) lists every saved step in the Adjustments panel ("Opened", "Exposure", "Crop", "Heal Spot 1: Size", …); clicking a step or moving with the arrow keys / Home / End shows that version, and an edit made on an earlier version drops the steps after it and starts a new branch. History is stored in the photo's `.eye` file (`_eye_` subfolder) next to the current state (the `History`/`HistoryPos` fields) — returns when reopening a photo with a saved fingerprint, and an in-memory session holds it between photos
- Documentary-style black & white: fast three-state toggle — toolbar button or the `B` key: color → **documentary** (panchromatic conversion with a slight red bias — like a yellow-red filter: bright skin, darkened blues + filmic S-curve: deep blacks, crisp mids, soft highlight rolloff) → **Tri-X 400** (emulation: stronger curve and fixed-pattern film grain per image, visible mostly in halftones); the histogram shows the result; reset on image change; saving honors the mode
- Compact dark UI: single toolbar line from the minimum window width (980 px); flat icon toolbar (one icon set, Segoe MDL2), dark context menus and tooltips
- Custom title bar: black, reduced height, with minimize/maximize/close buttons
- Always full-resolution decoding (JPG/PNG and RAW); finished images held in a short cache, scaling only for display
- Image navigation arrows on the left/right window edges
- Settings icon (⚙) top-right opens a panel of icon tiles instead of a drop-down menu: **Plugins** (Plugins…, and when plugins provide them Export, Commands, Tools, Plugin settings, Overlays — each opens its menu), **View** (Background, Preview quality, Remember previews, Presentation, Clear preview cache), **Edits & app** (Auto-save edits, About… — author, e-mail, GitHub, license); on/off tiles show their state with an accent frame and tick
- **Backgrounds** (⚙ → Background): the photo surround is a plain colour — dark (default), black, neutral 18 % grey (best for judging colour and tone), light grey or white; **your own picture goes behind the adjustments panel** (section headers turn slightly translucent over it) and the welcome screen — blurred (on by default) and darkened 0/30/60/80 % so the sliders stay readable, switched on/off without forgetting the file; remembered in the settings
- **Welcome screen** (no photo open): Open photo… / Open folder… buttons, a drop zone for files and folders (highlighted while dragging), up to 6 recent folders (newest first, missing ones skipped), the main shortcuts and "Choose a background picture…" (the same picture as behind the adjustments panel)
- **Presentation ("lights out")**: `F` / `F11`, the toolbar ⤢ button or ⚙ → Presentation — the whole monitor (taskbar included) on black, title bar, toolbar, status bar, adjustments panel, histogram and edge arrows hidden, the photo fitted; the mouse pointer hides after 2 s; ←/→ browse, `P` starts/pauses a slideshow (wraps around the folder; ↑/↓ change the interval 2–30 s, remembered), a short fading hint shows the file name and counter; `Esc`, `F` or `F11` returns to the previous window size and layout
- Automatic edit reset on image switch, and manual: `R`, the "Reset" button, double-click a slider (or the histogram — clears stretch points)
- Session edit memory: slider settings are remembered per photo while browsing a folder — going back to a photo restores the sliders and re-renders them (the current session state wins over the saved `.eye` file); **auto-save of edits** (on by default, ⚙ panel tile "Auto-save edits"): every committed edit — the same moments as an undo step, plus undo/redo, switching photos and closing the app — is written at once to the photo's `.eye` file (with the undo history), so edits, including plugin settings such as heal spots, come back after a restart without saving the photo; a photo that was never edited gets no file, an unchanged state is not rewritten, the write goes through a temp file, and a read-only folder shows "Edits not saved to .eye" in the status bar; switched off, `.eye` is written only by Save Photo
- **Where `.eye` files live**: all `.eye` files of a folder are kept in its `_eye_` subfolder (created on the first write; it is not listed as a photo), one per photo, named after the full file name (`photos\_eye_\DSC01670.ARW.eye`), so a RAW and a JPEG with the same name keep separate edits. An old `<name>.eye` next to the photo (earlier versions) is still read when `_eye_` has no file for that photo; it is left untouched, and the next save of that photo goes to `_eye_`, which then wins
- Saving the edited photo (Ctrl+S or the toolbar save button) via the **Save Photo** dialog — location and name choice (suggested `<current name>_eye`, the chosen format appends the extension) and format: **JPG (90% quality)** or **16-bit TIFF** (lossless 48 bpp RGB, real 16-bit values from RAW decoding — no 8-bit quantization, no compression — readers: WIC/Photoshop/GIMP); save at full source resolution with corrections applied (shadows, gamma, stretch points, black & white mode, corrections panel, crop/rotation — 90° steps and crop exact, free-angle bilinear; JPG/PNG at decoded size, RAW at native sensor dimensions, e.g. 4624×3088 from RW2); the edit-fingerprint file of the source photo (`_eye_\<name.ext>.eye`) with correction parameters and undo history is written, auto-loaded on reopen; the button is active only when some correction is active
- **AI assistant (Ollama, stage 1)**: the toolbar robot button opens a side window where you describe the result ("prepare this photo for a family album", "reportage style", "artistic black and white", "a bit warmer") and the model edits the basic settings itself, checks the result (image statistics, and a 1024 px preview for vision models) and refines it; a conversation per photo, follow-ups start from the current state, Stop keeps the changes made so far, and one Undo removes a whole request (step "AI: …"). Models come from a local Ollama (including its `-cloud` models) or Ollama Cloud (API key stored encrypted with DPAPI, or `OLLAMA_API_KEY`), listed with recommendations (★ sees the photo and calls tools; text-only; unsuitable). Sending to the cloud asks once for consent; camera data is sent only when enabled, never GPS or the file path. Design and later stages (plugins, crop, masks): `docs/ai-assistant.md`
- Drag & drop a file, opening via CLI argument, `Ctrl+O`
- Settings stored in `%AppData%\PhotographerEye\settings.json`

## Running

Portable: `dist\PhotographerEye.exe [file|folder]` — no install, .NET bundled in. Also handles RAW files (RW2, NEF, ARW, CR2/CR3, ORF, RAF, DNG…) via bundled LibRaw and HEIC/HEIF/HIF/AVIF via bundled LibHeif.

## Plugins

PhotographerEye loads .NET plugins that target `netstandard2.0` and reference `ImgViewer.Plugin.Abstractions` (`PluginSdk/`). The same plugin DLL works in the .NET 8 build and in the net6 Win7 build.

### SDK v2

- A plugin implements `IEyePlugin`. It has a `PluginManifest` (id, name, version, author, `Api = 2`, declared permissions) and an `Initialize(IPluginHost host)` method. In that method the plugin registers:
  - filters (`AddFilter`)
  - mask providers (`AddMaskProvider`)
  - importers (`AddImporter`)
  - exporters (`AddExporter`)
  - metadata providers (`AddMetadataProvider`)
  - commands (`AddCommand`)
  - presets (`AddPreset`)
  - list panels (`AddListPanel`): a section in the Adjustments panel with a selectable list (mouse, arrow keys, Home/End); the plugin supplies `Items`, `Selected` and `Select`, and calls `IListPanel.Refresh()` when its data change
  - overlays (`AddOverlay`, `OverlayDescriptor`): information drawn over the photo (lines, rectangles, ellipses, polylines, polygons, text and an RGBA raster such as a clipping map), switched on and off under Settings (⚙) > "Overlays". Shapes are given in fractions of the shown image or of the source photo (`OverlaySpace.Source` follows crop and rotation). `Draw` runs on the UI thread when the photo or the render changes, or when the plugin calls `IOverlay.Refresh()`; `OverlayRequest.Rendered` lazily returns the current preview. Overlays never take the mouse and are hidden in crop mode.
  - pointer tools (`AddTool`, `ToolDescriptor`, `ITool`): mouse tools on the photo (brushes, stamps, pickers) switched on under Settings (⚙) > "Tools", by their `Shortcut` or by `ITool.Active`; one tool is active at a time, Esc switches it off. While active, a press over the photo goes to `Pointer(PointerEvent, ICommandContext)` instead of panning (outside the photo the viewer still pans, the wheel still zooms): `Down`, `Move` with the button held, `Up` or `Cancel` (Esc, capture lost, tool off, photo closed), and `Hover` when `Hover` is set. Positions are fractions in `Space` (`Source` by default, or `Shown`) with `Inside`, the modifier keys, `ClickCount` and `ScreenPixel` (one screen pixel as a fraction of the image width). All changes of one press share one context, are previewed as they happen and become one undo step labelled with the tool. `Activated` / `Deactivated` get their own context, `Draw` draws like an overlay while the tool is active (`ITool.Refresh()`). Tools do not run in crop mode, during point picking, the eyedropper or mask editing. The input logic is in `Services/PointerToolSession.cs`, the window side in `MainWindow.Tools.cs`.
  - settings (`AddSetting`, `SettingDescriptor`): a plugin-wide choice, not stored per photo, shown under Settings (⚙) > "Plugin settings". The host keeps the choice in `settings.json` in the plugin's data folder. `IPluginSetting.Value` holds the stored choice as soon as `AddSetting` returns. `Changed` runs on the UI thread when the user picks a different choice, and may change a filter's `Stage`; the host then clears its stage caches, rebuilds the plugin panels and re-renders. A setting change is not an undo step.
- `host.History` (`IEditHistory`) exposes the undo steps of the current photo (`Steps` with labels, `Position`), `GoTo(index)` (like undo/redo to that step; the next edit drops the later steps) and a `Changed` event raised on the UI thread after each committed step, undo/redo and photo switch.
- `host.Events` exposes `ImageOpened`, `ImageClosed` (before switching to another photo and on exit), `BeforeSave` (which can cancel the save), `AfterSave`, `AfterExport`, `EditChanged` and `FilterToggled`. `EditChanged` is raised on the UI thread after each committed undo step, undo/redo and history jump (`FromHistory`), with the changed keys: `core.Exposure`, `core.Crop`, `core.Stretch`, ... for the core settings, `pluginId:filterId/paramId` for filter parameters, `pluginId:filterId#active`, `pluginId:filterId#mask` and `#order`. `FilterToggled` reports each filter switched on or off. `host.DataDirectory` is a writable folder for each plugin. `host.Imaging` provides blur, resize and JPEG/PNG encoding, and uses the GPU when one is available (`host.GpuAvailable`).
- **Commands** (`AddCommand`) get an `ICommandContext`. Besides filter values, active flags and presets it offers:
  - core settings: `CoreKeys`, `GetCore` / `SetCore` / `GetCoreRange` (`Exposure`, `Contrast`, `Temperature`, `Tint`, `Saturation`, `Highlights`, `Shadows`, `Whites`, `Blacks`, `Clarity`, `Dehaze`, `Sharpen`, `Denoise`, `ColorNoise`, `Gamma`, `Mono`; values are clamped to the slider range, all from `Services/CoreParams.cs`)
  - geometry: `GetGeometry` / `SetGeometry` (crop rectangle, aspect, quarter turns, straighten angle) and `ResetGeometry`
  - curves: `GetCurve` / `SetCurve` for the RGB curves, levels, histogram stretch (in display fractions or EV) and the RAW camera tone curve; `SetWhitePoint(x, y)` sets white balance from a neutral point of the photo, `SetWhiteBalanceFromNeutral(r, g, b)` from a linear colour measured on the Source image
  - pixels: `GetImage(Source | Developed | Rendered, maxLongSide)` (the source in linear sRGB for RAW; the photo at default settings, without edits or plugins, in sRGB; the current preview in sRGB) and `GetHistogram()` of the preview
  - interaction: `Ask(title, parameters)` (a dialog built from `ParamDef`s, which remembers the last answers), `PickOpenFile` / `PickSaveFile`, and `RunInBackground(label, work, done)`: `work` runs on a worker thread with progress in the status bar, and is cancelled by Esc, by switching photo or by a new background run of the same plugin; `done` runs on the UI thread with a fresh context
  - the viewer: `View` (`Zoom`, `SetZoom` with an optional centre, `FitToWindow`, `ActualSize`, `ShowOriginal`)
  - masks: `GetMask` / `SetMask` (`MaskInfo`) of any filter that supports masks
  - filter values also as text: `GetText` / `SetText` for text parameters (choice, colour, curve, point, file)

  `Placement` puts a command in the PLUGINS menu, on the toolbar (`ToolbarText`) or, with `CommandPlacement.Section` and `SectionFilter` = the id of one of the plugin's filters, as a button at the bottom of that filter's section in the Adjustments panel (caption `ToolbarText`, else `Label`); the section is rebuilt after the command runs, so a command may change the filter's `ParamDef.Choices`.

  All changes made by one command (or by one `done` callback) become a single undo step, labelled with `StepLabel` (the command label by default), and the preview re-renders once.
- **Filters** receive a `PluginImage` with float RGB planes in 0..1, the `FilterParams`, and a `RenderContext`. The context carries the stage, color space, preview flag, preview scale, full-resolution size, `ImageMeta`, cancellation token and progress callback.
- **Stages** decide where a filter runs:
  - `Base`: linear light, before everything else, including the manual exposure and white balance. Its result does not depend on them; they are applied on top of it. For a RAW photo it runs after the default brightness and before the camera tone curve. It is cached separately, so moving the exposure slider does not run it again.
  - `SceneLinear`: linear light, before the core adjustments.
  - `Display`: sRGB, after the core adjustments.
  - `Output`: after crop and rotate (for example a vignette).
- **Placement**: a filter goes either on the toolbar (a toggle button) or in the Adjustments panel (a collapsible section per `Group`, with a reset button). The run order is set in **PLUGINS ▸ Order…**: a window that lists the filters used on the photo grouped by stage (before tone / after tone and colour / after crop; "Show all filters" adds the unused ones), with up/down only inside a stage that has two or more of them, and "Default order". Filters run top to bottom, each on the result of the one before; the built-in adjustments always run at a fixed place between the stages, whatever order you used them in. The order is stored in `.eye`.
- **Parameter kinds**: `Slider`, `Toggle`, `Choice`, `Color` (hex, with an HSL picker), `Curve` (`x,y;...`, with a curve editor), `Point` (pick on the image), `File` (browse). Optional `IsIdentity` skips a filter while it would have no effect.
- **IDs are namespaced**: `pluginId:filterId`, and parameter values are stored as `pluginId:filterId/paramId`. Values that belong to plugins which are not installed are kept untouched in `.eye`, so a photo survives a round-trip through a machine without the plugin.
- **Masks**: any filter with `SupportsMask` (in every stage; masks of Output filters are mapped through crop and rotation) can be limited by one of the shapes below. While another mask is edited, the tool's Mask row offers *Work inside* to link the tool to that mask (`CanApplyInsideEdited`). This includes post-crop (Output) tools such as Post-crop vignette. The shapes:
  - a linear gradient (both handles on one point give no effect, not the whole photo)
  - a radial gradient (an ellipse that can be rotated: orange handle on the photo or the Rotation slider; `P[5]` in degrees). A new one is a circle in the middle of the part of the photo visible in the viewer (the photo centre when it fits; `MaskOverlay.VisibleCenterSrc`), 15% of the image height across whatever the aspect ratio (`MaskRender.RadialDefaultDiameter`, rx corrected by the aspect). The **Feather** slider (0–100, double-click resets to 50) sets `P[4]`, the soft fade from (1 − feather)·radius to the edge; the dashed inner ring on the photo follows it
  - a brush
  - a luminance range
  - a plugin mask provider (`plugin:<pluginId:maskId>`)

  A new area of a repeat group (*Add area*) of a filter with masks starts with the plugin's default settings (not those of the selected area) and a radial in the middle of the view, opened for editing, instead of acting on the whole photo; a new heal spot still takes the size and feather of the selected one. **Slow previews**: a live render that finishes after the filters or their masks changed (a filter switched on, a mask chosen, an area added) is not shown while the newer render is waiting (`PluginShapeKey`, `IsStaleRender`), so a slow filter such as trans-noise does not flash over the whole photo; a lagging slider value is still shown at once. A render replaced by a newer one (cancelled) is never shown.

  **Local corrections in any mask — sets of values**: the Adjustments panel has the whole-photo values (everywhere) and each mask's own values (`MaskSpec.Adjust`: CoreParam key → slider value, defaults left out), which add to the whole-photo values inside the mask (sum clamped to the slider range, `AdjustMask.Combine`); outside the mask only the whole-photo values apply. Choosing a mask therefore does not change the photo — a new mask has no values of its own, and the sliders switch to *Inside the mask*. Choosing another kind (e.g. Radial instead of a linked or linear mask) also makes a new mask with no values of its own: the previous mask's corrections do not carry over (Ctrl+Z brings them back). Under the mask icons *Sliders change: Whole photo | Inside the mask* picks which set the STANDARD / DETAIL sliders show and change (the hint lists the mask's values, e.g. "In the mask: Exposure +1.00"). A mask does not belong to the tool that made it: **every mask** — the Adjustments mask or the mask of any plugin filter (vignette, trans-noise area, B&W area …) — can have values of its own, stored on that mask (`MaskSpec.Adjust`, `_adjMaskKey`). Whichever mask is being edited (from its marker, its mask icons or *Edit that mask*) gets the STANDARD / DETAIL sliders: they switch to *Inside the mask* of that mask by themselves, so every slider edit changes only its inside until **Done** (or Esc), and editing another mask moves the sliders to that mask's values (`EnterAdjMaskSet(key)`, `EndMaskEdit`). A linked mask has the shape of its source but values of its own (kept on the link). The *Sliders change* row is under the mask icons of every filter too. Local corrections of a filter's mask act also when the filter itself is off. Toolbar shadows/gamma, R/G/B curves, histogram levels and B&W stay whole-photo; presets and the histogram bake set the whole-photo values; the white-point eyedropper in the mask set stores the difference to the whole-photo white balance. The photo is rendered with the whole-photo values and with the combined values (`PluginRenderJob.AdjustMaskExtras`, one entry per mask with values) and each one is added by its mask (`onto + mask × (masked − whole photo)`, masks computed on the whole-photo render), so several masks with their own corrections add up; without own values there is no second render. The values stay with the mask when it is linked, copied, unlinked, edited on the photo or set by a plugin (`SetMask` changes the shape only); removing the mask drops them (undo brings them back). UI state in `MainWindow.AdjustSets.cs`.

  The mask is chosen with a row of icons (whole photo, linear, radial, brush, luminance, then plugin masks). In the Adjustments panel the mask controls sit in a collapsible **MASK** section at the top (like the plugin sections; key `panel:mask`, closed by default, the header names the mask kind and "own values"; it opens by itself when a mask is chosen from a marker). The **histogram** icon on the Adjustments header bar, next to *Presets*, shows or hides the histogram (it hides when you switch photos). Masks can be inverted. **Mask colour**: while a mask is edited, a button left of the histogram (at the right edge when the histogram is hidden; `BtnMaskTintSide`), the *Overlay* toggle on the mask bar and the `O` key switch the red mask colour on and off, so the clean photo with the result can be checked at any time (`SetMaskTint`). They are edited on the image through `Controls/MaskOverlay.cs`. **Mask markers**: while a mask is being edited, the other masks of the photo (all tools and plugins) show as small markers on the photo — the centre of a radial, the middle of a linear gradient, the painted point nearest the middle of a brush (`MaskRender.PinPoint`; luminance and plugin masks have none). The markers icon at the start of the mask row in the MASK section shows them also when no mask is being edited (`ShowMaskMarkers` in settings). Hovering a marker outlines its mask and names it (kind — owner, area of a repeat group, inverted); clicking it edits that mask, expanding its section, selecting its area and scrolling it into view. Markers closer than 16 px merge into one with a count that opens a list. With no mask being edited only the markers take the mouse (`HitTestCore`), the photo still pans and zooms; markers hide in crop, compare and presentation mode (`MainWindow.MaskPins.cs`). **Linked masks**: the link icon at the end of the mask row lets Adjustments or a plugin filter use the mask of another tool instead of drawing its own (e.g. a plugin uses the radial made in Adjustments). It is stored as `Kind = "link"` with `Ref` = the key of that mask; `PluginEditState.Resolve` gives the source mask wherever masks are rendered (`MaskFor`, `AdjustMask.For`, the SDK `GetMask`), so editing the source changes both. Invert on a link is relative to the source. A link cannot point at another link. When the source mask is removed or replaced, links to it become own copies (`DetachLinksTo`). The linked mask shows which mask it uses, with *Edit that mask* and *Unlink* (own copy). The source marker lists the masks that also use it. The link menu has two parts: *Use the same mask* (a link) and *Copy the mask* (an own duplicate in the same place, opened for editing; the owner name in labels and markers tells them apart). Pointing at an entry of the link menu (or of the list of merged markers) shows that mask on the photo — an amber outline and area (`HighlightMask`, `MaskOverlay.SetHighlight`) — until the menu closes, so it is clear which mask the entry means. While a shared mask is edited, the mask bar says who shares it and offers *Edit only for …*: opened from a linked tool (*Edit that mask*), that tool gets its own copy and editing goes on there; otherwise the other tools keep the current shape as copies (`_maskEditVia`, `UpdateMaskBarShared`). Test hook `PE_OPEN_SETTINGS=maskedit:<filter key>`.
- **Presets**: plugins can ship presets, and users can save their own to `%APPDATA%\PhotographerEye\Presets`. Preset keys are `core.Exposure`, `core.Contrast` and the other core controls, plus plugin keys.
- **Built-in filters**: `core:lut` applies a `.cube` 3D LUT, either a built-in profile (warm, cool, tealorange, matte, vivid) or a file from `%APPDATA%\PhotographerEye\LUTs` or `luts\` next to the executable. `core:local` provides masked local adjustments.
- **v1 compatibility**: old `IPlugin` DLLs still load through `V1Adapter`. Each v1 feature becomes a Display filter `v1.<file>.<name>:<featureId>` with parameters `p0..pN`, and v1 `.eye` keys are migrated when a photo is opened.

### Packages, trust and failure handling

- **Package format**: a `.pepkg` is a zip that contains `manifest.json` (`id`, `name`, `version`, `author`, `api`, `entry`, `permissions`) and the assemblies.
- **Install**: `Settings ▸ Plugins… ▸ Install` opens a trust dialog before anything is executed. The dialog shows:
  - the manifest
  - the SHA-256 of the package and of the entry assembly
  - the Authenticode signature status
  - the plugin types and dependencies, read from assembly metadata without loading the code
  - the declared permissions

  Packages are installed to `%APPDATA%\PhotographerEye\Plugins\<id>\`. Plain `.dll` files are still accepted.
- **Automatic disabling**: a plugin is disabled after 3 consecutive failures (exceptions in a render, mask, importer, exporter or command). A preview render that takes longer than 8 s disables it immediately. The reason is saved in `settings.json` (`PluginDisabledReason`) and shown in the Plugins window, where the plugin can be re-enabled. Each plugin inside a package can be enabled or disabled separately.
- **Limitations**:
  - Plugins run **in-process**. There is no process isolation or sandbox: a plugin has the same rights as the app.
  - Permissions are **declarative only**. They are shown to the user before install but not enforced.
  - The timeout stops waiting for a hung preview and disables the plugin, but it cannot kill the plugin's thread. Install only plugins you trust.

## Installation

Two Windows installers, built with Inno Setup (`installer\PhotographerEye.iss`, driven by `installer\build.ps1`):

- `PhotographerEye-Setup-Win10-11-1.00.exe` — Windows 10 (1607+) / 11, GPU acceleration (ComputeSharp/DirectCompute).
- `PhotographerEye-Setup-Win7-1.00.exe` — Windows 7 SP1 x64, CPU-only build (`net6.0-windows`, GPU compiled out, identical corrections results).

Both are fully self-contained: the .NET runtime, LibRaw/LibHeif codecs, the `dcraw_emu` fallback and the VC++ 2015-2022 redist are packed inside, so nothing is downloaded during installation. Builds:

```
powershell -ExecutionPolicy Bypass -File installer\build.ps1          # both installers
powershell -ExecutionPolicy Bypass -File installer\build.ps1 -Win7    # only the Win7 one
```

The Win7 build is produced from the same sources: `ImgViewer.csproj` switches to `net6.0-windows` with `-p:Win7=true`, and `Adjust16.Gpu.Stub.cs` replaces the GPU layer (CPU path returns the same pixels as the GPU path, verified by the harness). Requires Inno Setup 6 (`ISCC.exe`, e.g. `%LOCALAPPDATA%\Programs\Inno Setup 6`).

It closes any running PhotographerEye, starts it with an isolated app-data dir and `PHOTOGRAPHEREYE_DEBUG=1`, and writes `UI-TEST.md` (IN/OUT pixel deltas and a verdict per core slider and plugin parameter).
- Phases:
  - Mask 1: radial, upper left (30 %/25 %).
  - Mask 2: radial, lower right (70 %/62 %).
  - Pin-click re-entry of Mask 1.
  - Invert outside Mask 1.
  - Brush: band in the lower left.

## Structure

- `MainWindow.xaml(.cs)` — toolbar, title bar, navigation, saving, view refresh, settings
- `Controls/ImageViewer.cs` — zoom/pan/fit (layout rendering, no matrix transforms)
- `Controls/CropOverlay.cs` — crop frame UI: shades, rule-of-thirds grid, 8 resize handles (aspect-locked), move and outside-drag straighten, frame derived from the live displayed image rect; overlay rendering and hit-testing are clipped to the visible image area, so the crop lines and handles never cover the toolbar, status bar or adjustments panel (also when the image is zoomed/panned beyond the window)
- `Controls/HistogramOverlay.cs` — top-right histogram + interactive stretch points
- `Controls/PhotoshopSlider.cs` — Photoshop-like slider behavior (track click, precise label/number dragging with modifiers, value typing, arrow-key steps)
- `Imaging/RawDecoder.cs` — RAW decoding (LibRaw: 16 bit/channel **linear** (LibRaw gamma off, `-g 1 1` in fallback), mixed highlight mode, camera white balance, 16-bit pair cache + Bgra32 preview; fast RAW preview: `TryDecodePreview` — largest built-in JPEG/camera thumbnail, LRU cache ~12, `TryGetInfoHeader` — header dimensions without decompression; EXIF orientation (tag 274) applied immediately to header and preview, so portrait RAWs have correct proportions from open and fit-to-window works (`AlignToPreview` aligns dimensions to preview aspect for formats without EXIF in the container); starting preview = neutral base process: for Sony a tone curve fitted to the embedded JPEG preview (`Imaging/CameraTone.cs`, knots → EV LUT), otherwise exposure normalization from the luminance percentile (99.5% → ~0.93) + Reinhard tonemap + sRGB encoding; when the internal decode fails or yields garbage — automatic fallback to the bundled command-line tools: `thirdparty/libraw22/dcraw_emu.exe` (LibRaw 0.22.2; handles e.g. plain NEFs from Nikon Z6 III) and `thirdparty/librawhe/dcraw_emu.exe` (LibRaw fork with the Nikon NEF High Efficiency = TicoRAW/JPEG-XS decoder; decodes the HE variant, the HE* variant stays unsupported — instead of garbage the app shows a readable message)
- `Services/AdjustmentsProcessor.cs` — 8-bit pipeline for JPG/PNG: develop-operation order (white-balance+dehaze LUT → EV regions → clarity/sharpening → luminance tonemap with exposure) + gamma, manual stretch map, histogram
- `Imaging/Adjust16.cs` — RAW pipeline at 16 bit/channel in the **linear-scene** domain (white-balance+dehaze LUT → highlight/shadow regions in EV on log-luminance → clarity/sharpening → scene Reinhard tonemap with exposure and highlight anti-desaturation → saturation → sRGB encoding → gamma/manual map/mono/grain → histogram); for RAWs with a camera curve dehaze is applied after the tonemap (display domain), and WB enters without dehaze
- `Imaging/Adjust16.Gpu.cs` — GPU backend (ComputeSharp/DirectCompute) for `Adjust16`: hardware GPU detection (discrete-card preference), RAW edit operation shaders (incl. ToneKernel — EV LUT), automatic CPU fallback when no GPU or on error
- `Imaging/LinearRender.cs` — linear RAW gains: exposure in EV + temperature as plain multiplication in linear scene space (before regions and tonemap); linear→sRGB LUTs for display encoding
- `Imaging/Raw16.cs` — planar 16-bit RGB image, deinterleaving, 4×4 Bayer-dithered quantization, interleaving for TIFF
- `Imaging/PhotoGeo.cs` — non-destructive geometry (`GeoState`: 90° quarter turns, free-angle straighten, normalized crop): lazy quarter-turn+crop transforms for display, bilinear auto-inset rotation for both 8-bit BGRA and planar 16-bit RAW (save path), crop rect preserved across quarter turns
- `Services/CoreParams.cs` — table of the basic adjustments (plugin key, `EyeState` field, undo label, range, default, slider and value-text names in `MainWindow.xaml`, value format) and of the other edit fields (undo label, EditChanged key, coalescing group); the panel sliders (events, value text, reset, double-click reset, `.eye` capture/apply), presets, `GetCore` / `SetCore` / `GetCoreRange`, `HistoryLabels`, `EditChangeKeys` and `HistoryCoalesce.GroupKey` all read it, so a new slider is a table entry plus the slider in the XAML and its use in the renderer
- `Services/EyeFile.cs` — `.eye` correction fingerprint (JSON) next to the source, auto-applied on open; stretch points stored in EV (`.eye` files with old display-fraction points converted on load)
- `Imaging/NoiseReduction.cs` — wavelet noise reduction for luminance and color (noise estimate, chroma speckle median, threshold plan, a trous decomposition; shared by CPU 16-bit, JPG and the GPU kernels in `Adjust16.Gpu.cs`)
- `Imaging/PhotoOps.cs` — EV shadow/highlight region masks (scene log-luminance), white-balance/dehaze LUTs, luminance tonemap (scene Reinhard for RAW — always active as the base process, display gamma-2.2 S-curve for JPG), saturation, clarity/sharpening (unsharp), temperature measurement from a sample
- `Imaging/ManualStretch.cs` — stretch-point map in scene EV (folded into the tonemap LUT before sRGB encoding)
- `Imaging/HeifDecoder.cs` — HEIC/HEIF/AVIF decoding (in-proc LibHeif): `IsHeif`, `GetInfo` with orientation per container/EXIF rules, `LoadScaled`/`DecodeFull` with a short LRU cache (3), `ExifBytes` for the metadata bar; in-file ISOBMFF parser (`ContainerHasTransforms`) detects `irot`/`imir`/`clap` in `ipco` (container transforms are already applied by libheif, so EXIF is skipped then)
- `Services/ImageFolder.cs`, `Services/SettingsStore.cs` — file list, settings
- `Services/PhotoMeta.cs` — file metadata for the bottom bar (`PhotoMetaReader.Get`, cached): RAW via LibRaw (`ImageParams`/`ImageOtherParams` — header only, no decompression), HEIC/HEIF/AVIF via own minimal TIFF parser (`ParseTiff` — LE/BE, IFD0 + ExifIFD: Make/Model, DateTimeOriginal, ExposureTime/FNumber/FocalLength/ISO), the rest via `BitmapDecoder` EXIF; no data → empty label
- `PluginSdk/` — plugin contract (`ImgViewer.Plugin.Abstractions`, netstandard2.0)
- `PluginHosting/` — plugin host: loading/registry/failure handling (`PluginManager.cs`; every registration kind lives in one `RegistrationStore` per plugin and is read with `PluginRegistry.All<T>()`, so a new kind needs no change in the registry or in the Plugins window summary), stage pipeline (`PluginPipeline.cs`), per-photo state (`PluginState.cs`), masks (`MaskRender.cs`), LUT + local filters (`BuiltInFilters.cs`), `.pepkg` + trust (`PluginPackage.cs`, `TrustDialog.cs`), presets, importer bridge; UI in `MainWindow.Plugins.cs`, commands and overlays in `MainWindow.PluginCommands.cs`, pointer tools in `MainWindow.Tools.cs`
- `tools/Harness/` — logic tests
- `scripts/` — E2E UIA tests and helpers

## Debugging
